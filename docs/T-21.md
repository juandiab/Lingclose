# T-21 — Registro de comidas con LLM: contrato de interfaces

Especificación de Juampa (2026-10-27, dos mensajes): detección automática comida / etiqueta / no comida; porción base concreta con kcal, carbohidratos, proteínas y grasas en campos editables con supuestos; etiquetas con su base (100 g, 100 ml o porción) sin confundirla con lo consumido; slider 1,0–5,0 paso 0,1 que recalcula **siempre desde la base** sin llamar al LLM; guardar nutrientes ajustados + cantidad + base + multiplicador; correcciones manuales protegidas; sin ajuste inútil cuando no hay cifras; respuestas estructuradas por proveedor; nada se guarda solo; desconocido nunca es 0. Configuración del LLM en Opciones con catálogo autenticado, precios con fuente o "No publicado", recomendación, modelo elegido plegado con "Cambiar modelo", búsqueda, análisis bajo demanda enviando solo foto y descripción, errores claros, sin reintentos cobrables.

Reparto: **Fable** escribió `Packages/LingoCore/Sources/LingoCore/Nutrition/{Nutrients, NutrientField, PortionBasis, FoodAnalysisKind, FoodAnalysis, FoodAnalysisParser, FoodAnalysisParserError, NutrientLimits}.swift` (hecho, 8 tests). **Opus A** = §3 (registro y persistencia). **Opus B** = §4 (servicios LLM). **Sonnet C** = §5 (UI), después de A y B. Nadie toca archivos de otro.

## 1. Tipos ya existentes (LingoCore `Nutrition/`)

- `Nutrients { kcal, carbsG, proteinG, fatG: Double? }` — `nil` = desconocido. `scaled(by:)` (desde la base), `overridden(by:)` (campo a campo), `isUnknown`, `subscript(NutrientField)`.
- `NutrientField: kcal | carbsG | proteinG | fatG` (raw `kcal`, `carbs_g`, `protein_g`, `fat_g`).
- `PortionBasis: per100g | per100ml | perServing(description:grams:) | estimatedServing(description:grams:)` — `isLabel`, `typeName`, `init?(typeName:description:grams:)`, Codable `{type, description, grams}`.
- `FoodAnalysisKind: food | nutrition_label | not_food`.
- `FoodAnalysis { kind, name?, basis?, baseNutrients, confidence?, assumptions?, unreadableFields }`, `hasAnyNutrient`.
- `FoodAnalysisParser.parse(_ data:)`, `.parse(text:)`, `.parse(object:)` → `FoodAnalysis` o `FoodAnalysisParserError`.
- `NutrientLimits`: kcal 0…5000, gramos 0…2000, base 0…5000 g, confianza 0…1, `portionMultiplier` 0,5…5,0 (media porción a cinco; arranca en 1,0 = la base, ajuste de Juampa del 27-oct), `portionStep` 0,1.

## 2. Esquema JSON que pide todo proveedor (respuesta del modelo)

```json
{
  "kind": "food | nutrition_label | not_food",
  "name": "string | null",
  "basis": { "type": "per_100g | per_100ml | per_serving | estimated_serving", "description": "string | null", "grams": "number | null" },
  "nutrients": { "kcal": "number | null", "carbs_g": "number | null", "protein_g": "number | null", "fat_g": "number | null" },
  "confidence": "number 0–1 | null",
  "assumptions": "string | null (breve)",
  "unreadable": ["nombres de campos ilegibles de la etiqueta"]
}
```

Instrucciones al modelo (mismo texto base en todos los proveedores, `LLMPromptBuilder`): decidir `kind` sin que el usuario lo diga; para comida, proponer **una porción base concreta** (`estimated_serving` con descripción y gramos aproximados) aunque no se indique cantidad y estimar los cuatro nutrientes para esa porción; para etiqueta, copiar la base legible (`per_100g`, `per_100ml` o `per_serving` con su descripción) y los valores legibles, dejando `null` lo ilegible y listándolo en `unreadable`; nunca inventar; `not_food` cuando no hay comida ni etiqueta; responder solo con el JSON. El parser tolera vallas ```json``` y texto alrededor.

## 3. Registro y persistencia (Opus A)

Archivos: `Packages/LingoCore/Sources/LingoCore/Nutrition/MealNutritionRecord.swift`, `MealNutritionSource.swift`, `PortionAdjustment.swift`; `Packages/LingoCore/Sources/LingoCore/Store/StoreSchema.swift` (migración v2), `Store/SQLiteStore+MealNutrition.swift`; tests `Packages/LingoCore/Tests/LingoCoreTests/MealNutrition*.swift`, `SchemaMigrationTests.swift` (añadir caso v1→v2).

```swift
public enum MealNutritionSource: Sendable, Hashable, Codable {
    case llm(provider: String, model: String)   // identificadores, nunca claves
    case label(provider: String, model: String)
    case manual
}

/// Lo que se guarda junto al evento `meal` (tabla propia; el contrato compartido no cambia).
public struct MealNutritionRecord: Sendable, Hashable, Codable {
    public var eventID: String
    public var source: MealNutritionSource
    public var kind: FoodAnalysisKind            // food | nutrition_label
    public var name: String?
    public var basis: PortionBasis
    public var baseNutrients: Nutrients          // la base original, intacta
    public var multiplier: Double                // 1,0…5,0, paso 0,1
    public var overrides: Nutrients              // correcciones manuales; nil = sin corrección
    public var assumptions: String?
    public var confidence: Double?
    public var analyzedAt: UTCInstant?
    public var updatedAt: UTCInstant
    /// `overrides[f] ?? base[f] * multiplier`, campo a campo. Nunca acumula.
    public var effectiveNutrients: Nutrients { baseNutrients.scaled(by: multiplier).overridden(by: overrides) }
}

/// Reglas puras del slider y las correcciones (la UI solo las muestra).
public enum PortionAdjustment {
    public static func clamp(_ m: Double) -> Double        // a 1,0…5,0 y al paso 0,1 (redondeo a 1 decimal)
    public static func adjusted(_ base: Nutrients, multiplier: Double, overrides: Nutrients) -> Nutrients
    /// Texto legible: kcal entero; gramos con 1 decimal si no es entero. nil → nil (la UI pone "Desconocido").
    public static func display(_ value: Double?, field: NutrientField) -> String?
}
```

Persistencia: migración `v2` con tabla `meal_nutrition (event_id TEXT PRIMARY KEY REFERENCES events(event_id), source_json TEXT NOT NULL, kind TEXT NOT NULL, name TEXT, basis_json TEXT NOT NULL, base_json TEXT NOT NULL, multiplier REAL NOT NULL, overrides_json TEXT NOT NULL, assumptions TEXT, confidence REAL, analyzed_at_epoch_s INTEGER, updated_at_epoch_s INTEGER NOT NULL)`; `PRAGMA user_version = 2`. `SQLiteStore`: `upsertMealNutrition(_:)`, `mealNutrition(eventID:)`, `deleteMealNutrition(eventID:)` y `saveMeal(event:nutrition:)` que escribe el evento (`upsertEvent`, `carbs_g` = `effectiveNutrients.carbsG`) y la fila **en una transacción**. No se exporta al `.lingoscan` (el contrato §5.3 solo lleva `carbs_g` y `text`); un evento sin fila sigue siendo un registro válido (compatibilidad). Tests: v1→v2 conserva datos; guardar/reabrir devuelve exactamente la base y el multiplicador; 200 kcal/30 g × 1,5 = 300/45 y vuelve a 200/30 con 1,0; corrección manual de carbohidratos sobrevive al cambio de multiplicador; `nil` sigue `nil` tras guardar.

## 4. Servicios LLM (Opus B)

Archivos: `LingoScan/Services/LLM/**` (un tipo por archivo), tests `LingoScanTests/LLM/**`, fixtures `LingoScanTests/Fixtures/LLM/<proveedor>-<caso>.json`.

```swift
enum LLMProviderID: String, CaseIterable, Codable, Identifiable { case anthropic, openai, grok, openrouter, deepseek, gemini; var displayName: String }

enum ImageSupport: Sendable, Hashable, Codable { case confirmed, none, unconfirmed }   // "No confirmado" en UI

struct ModelPricing: Sendable, Hashable, Codable {
    var inputUSDPerMTok: Double?; var outputUSDPerMTok: Double?
    var source: String      // URL o "catálogo del proveedor"; obligatorio si hay precio
    var asOf: String        // "2026-10"
}

enum ModelRecommendation: Sendable, Hashable, Codable { case recommended(reason: String), notRecommended(reason: String), unknown }

struct LLMModel: Identifiable, Sendable, Hashable, Codable {
    var id: String; var provider: LLMProviderID; var displayName: String
    var imageSupport: ImageSupport; var pricing: ModelPricing?      // nil → "No publicado"
    var recommendation: ModelRecommendation
    var maxOutputTokens: Int?; var supportsReasoningControl: Bool
}

enum LLMError: Error, Sendable, Hashable {
    case unauthorized, quotaExceeded, rateLimited, refused(String), incomplete(String), modelLacksVision,
         network(String), server(status: Int, message: String), invalidResponse(String)
}

struct FoodAnalysisRequest: Sendable { var imageJPEG: Data?; var description: String?; var locale: String }   // nada más sale del teléfono

protocol LLMProvider: Sendable {
    var id: LLMProviderID { get }
    func listModels(apiKey: String) async throws -> [LLMModel]      // catálogo autenticado; acceso ≠ saldo
    func analyze(_ request: FoodAnalysisRequest, model: LLMModel, apiKey: String) async throws -> FoodAnalysis
}

protocol HTTPTransport: Sendable { func send(_ request: URLRequest) async throws -> (Data, HTTPURLResponse) }
struct URLSessionTransport: HTTPTransport   // real
```

- `LLMKeyStore` (actor): `save(_ key: String, for: LLMProviderID)`, `key(for:)`, `delete(for:)` sobre `SecretItemStoring` (Keychain `com.otalvaro.lingoscan.llm`, cuenta = id del proveedor, `AfterFirstUnlockThisDeviceOnly`). La clave nunca aparece en `description`, logs, errores ni en el `.lingoscan`. Tests con `InMemorySecretItem` (`LingoScanTests/RecoveryServiceTests.swift`).
- `LLMSettingsStore` (`UserDefaults`): proveedor y modelo elegidos (`LLMModel` codificado), nunca la clave.
- `LLMCatalog`: tabla estática de precios e `imageSupport` **conocidos** con `source` (URL de la página de precios) y `asOf`; lo que no esté → `pricing nil` / `.unconfirmed`. Para Anthropic, `GET /v1/models` trae `capabilities` (ver skill `claude-api`); Haiku 5.5 `claude-haiku-5-5` 0,10/0,50 $/MTok (fuente: skill `claude-api`, 2026-10) y es la recomendación por defecto. Recomendar solo con imágenes confirmadas y precio conocido; explicar por qué.
- Proveedores, un archivo cada uno: `AnthropicProvider` (Messages API, imagen `base64` `image/jpeg`, salida estructurada con `tools` + `tool_choice` forzado al esquema de §2, `max_tokens` explícito, sin `thinking` para el análisis; modelos: `GET /v1/models`), `OpenAIProvider` (`/v1/models` + Chat Completions con `response_format: json_schema` strict e imagen `image_url` data URL; para modelos de razonamiento `reasoning_effort: "low"` y `max_completion_tokens`), `GrokProvider` y `OpenRouterProvider` (API compatible con OpenAI; OpenRouter `/api/v1/models` publica precios y modalidades por modelo → úsalos como `source: "catálogo de OpenRouter"`), `DeepSeekProvider` (solo texto: `imageSupport: .none`; `response_format: json_object`), `GeminiProvider` (`/v1beta/models` + `generateContent` con `responseMimeType: application/json` y `responseSchema`, `inlineData` para la imagen, `thinkingConfig.thinkingBudget: 0` donde aplique). Verifica identificadores y campos en la documentación oficial con WebFetch al implementar; si no puedes confirmar algo, deja `.unconfirmed` / `nil`, no inventes.
- `analyze` con imagen exige `model.imageSupport == .confirmed`; si no, `LLMError.modelLacksVision` antes de llamar. Sin reintentos automáticos. HTTP 401/403 → `unauthorized`; 402 o mensaje de saldo → `quotaExceeded`; 429 → `rateLimited`; respuesta sin JSON válido → `invalidResponse`; `stop_reason`/`finish_reason` de truncado → `incomplete`; rechazo de contenido → `refused`.
- Tests con `FixtureTransport` (respuestas grabadas por proveedor): catálogo → `[LLMModel]`; análisis correcto → `FoodAnalysis`; 401, 429, truncado, JSON roto; `grep` de que ninguna clave de prueba sale en `String(describing:)` de errores ni en logs. Ninguna llamada real.
